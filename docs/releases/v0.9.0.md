# jpdev v0.9.0

This release keeps a scoped pull-request run scoped when a workflow creates files inside the
clone, and stops a test suite from waiting on an inherited standard input
([issue #48](https://github.com/Judgment-Pack/judgment-pack-devkit/issues/48),
[pull request #49](https://github.com/Judgment-Pack/judgment-pack-devkit/pull/49);
[issue #46](https://github.com/Judgment-Pack/judgment-pack-devkit/issues/46),
[pull request #50](https://github.com/Judgment-Pack/judgment-pack-devkit/pull/50)).

## Workflow-created paths and `--changed`

An untracked path that no `.gitignore` rule covers counts as a changed path, so a checkout or an
output a workflow places inside the clone made every pull request run the whole list. The CI
template's parity example now moves the other repository's checkout out of the clone, under the
runner's temporary directory, before any check runs. When an untracked path is unmapped, the
selection report says so in those words: a workflow-created path belongs outside the clone or in
`.gitignore`. The adopting guide states the rule beside the changed-path selection.

## Test suites and standard input

The cleanup tests' git helper no longer hands a git command the runner's standard input: it is
closed unless the helper feeds input explicitly, and every call carries a timeout. A test holds
the helper to that with a socket on standard input. The kit's own `run()` already closed standard
input; the tests now match it.

## Operating limits

Those of v0.8.0. A repository that keeps a workflow-created path inside its clone must add it to
`.gitignore` or `--changed` runs the whole list; the report names the path.
