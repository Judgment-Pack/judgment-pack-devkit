# jpdev v0.11.0

This release lets a repository that publishes prereleases use the release evidence gate, and
gives a `workflow_dispatch` run of a release workflow a stated meaning
([issue #54](https://github.com/Judgment-Pack/judgment-pack-devkit/issues/54),
[pull request #55](https://github.com/Judgment-Pack/judgment-pack-devkit/pull/55)).

## The tag grammar

`ci-evidence.json` gains an optional `tag` member. With `prerelease: true` the gate accepts a
SemVer prerelease suffix after `vX.Y.Z` (`-rc.1`, `-alpha.1`; identifiers alphanumeric or
hyphen, numeric ones without leading zeros, no build metadata), still bound to the exact
commit and still an annotated tag. The default is unchanged: `vX.Y.Z` only. A repository that
tags prereleases sets `prerelease: true` and widens its own tag trigger and syntax step.

## Dispatch runs

An optional `dispatch` member says what a `workflow_dispatch` run of the release workflow
validates. The default, `none`, refuses such a run (`dispatch-not-gated`). With
`validates: branch-tip` the run validates the default branch's tip, reads no tag, and decides
`validated`, never `reuse`; the decision record and the step outputs carry the decision and the
mode, and a publication step accepts only `reuse`. The kit's own release workflow exposes the
decision and its package job requires `reuse`.

## Operating limits

Those of v0.10.0. With `branch-tip`, exit 0 means `reuse` or `validated`: an adopter gates
publication on the `decision` output, not on the exit status.
