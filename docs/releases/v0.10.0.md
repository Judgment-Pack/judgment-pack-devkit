# jpdev v0.10.0

This release hardens the release evidence gate that v0.8.0 introduced, and ships the
template other repositories adopt it from
([issue #37](https://github.com/Judgment-Pack/judgment-pack-devkit/issues/37),
[pull request #52](https://github.com/Judgment-Pack/judgment-pack-devkit/pull/52)).

## The release evidence gate

A release reuses the whole-list CI run that `main` already produced at the exact release
commit instead of running the checks again, and it reuses nothing else. The gate
(`lib/release_evidence.py`, vendored as `scripts/dev/release_evidence.py`) identifies the
workflow by path and name, accepts only a completed, successful run on the default branch
from a trusted event, bound to the exact commit, with every required job and matrix leg
present on a GitHub-hosted runner with the configured labels and no skip that is not
permitted. It selects the newest attempt by start time across every run of the workflow at
that commit, whatever triggered it, and refuses when that attempt failed, was cancelled or is
still running. The workflow file, the manifest, named pin files and pinned toolchains must
match the release's; the release runner's image and tools are compared with the evidence
run's. Every decision, reuse or refusal with its code, goes to the log, to a file and to a
`release-evidence-<attempt>` artifact. Unavailable, partial, stale or incompatible evidence is
a refusal; nothing runs automatically in its place. The documented fresh route is the
operator's: re-run the main run's jobs at the commit, or dispatch the CI workflow on `main`
while it still names the commit, then re-run the release's failed jobs once.

`.github/ci-evidence.json` moves to schema 2; `templates/ci-evidence.json` is the adopters'
starting point, with the places for matrix legs, pinned inputs and tag-sensitive checks
marked. A run of the workflow at the commit that is newer than the selected one and did not succeed refuses (`run-newer-failed`), whatever triggered it; an unreadable evidence artifact is a recorded refusal (`unavailable-or-malformed`), never a crash; a fork pull request or a run on another branch at the release commit neither blocks nor is accepted. The gate is held by 85 tests over a fake API, one per refusal class, and by 34 mutants
that remove one safeguard each.

## Operating limits

Those of v0.9.0. Capture runs only on `main`, so a repository's first live capture is the
first push after adoption. The kit's own verify job took about 60 s when it called the CI
workflow and about 15 s through the v0.8.0 gate; the hardened gate makes the same API reads
plus one and is first measured at this release.
